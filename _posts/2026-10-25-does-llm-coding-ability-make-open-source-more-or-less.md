> Open source in its current form doesn’t make sense anymore. “Given enough eyeballs, all bugs are shallow” is still true but now we have artificial eyeballs. - [What I Believe About the Future of Software Development](https://thorstenball.com/blog/2026/09/19/what-i-believe-about-the-future-of-software-development/)

I'm not exactly sure what this means. In theory artificial eyeballs will find it cheap and easy to file an easy-to-verify issue or, more likely, put up a PR to fix it. But perhaps it means that having a small group of human maintainers well get overwhelming? Or that bots are _less_ likely to contribute back? 

It's true that AI has pushed the build-vs-buy pendulum back towards build nearly instantaneously. But I do think it's short sided. And if you're in a race to improve education through tech, do you really want anyone rebuilding JIRA from scratch? If code is cheap, is the impulse to keep it to yourself and build fast? Or is the impulse to open source generalizable solutions because (1) your moat is no longer about how fast you can build, (2) if we're all generating our UI the code will be the same anyway might as well pool resources, (3) modifying a shared base to exactly what you need is cheap
